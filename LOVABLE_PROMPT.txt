## Iteration 4 — Move elements in edit mode

In admin mode, users should be able to move existing elements by dragging them to a new position on the canvas.

### Desired behavior

1. In admin mode: when the user clicks and holds an existing element, it should be draggable across the canvas.
2. While dragging: show the element semi-transparent (opacity ~0.6) snapped to the 60px grid at the new position.
3. Show a green highlight where the element will land if the position is free, and a red highlight if the position is occupied.
4. On drop: move the element to the new grid position if it is free. Cancel the drag and keep the original position if occupied.
5. Collision detection: ensure no part of the dragged element overlaps any other element.
6. Dragging an element must NOT trigger placement of a new element (do not call onCellClick).

### Technical implementation

- Add `onMoveElement: (id: string, newX: number, newY: number) => void` prop to FloorPlanCanvas.
- Use pointer events (onPointerDown/onPointerMove/onPointerUp) for drag — do not use the HTML5 drag API.
- CELL = 60px. Snap to grid: `Math.floor(pixelOffset / CELL)`.
- In Index.tsx: add a `moveElement` function that updates the element's x/y, and pass it as the `onMoveElement` prop.

### Existing functionality that must NOT change
- Clicking an empty cell places a new element (onCellClick works as before)
- Clicking an existing element selects it (onElementClick works as before)
- Delete button in the sidebar panel
- Resize inputs in the sidebar panel
- Booking mode is unaffected

All UI text remains in Norwegian.
